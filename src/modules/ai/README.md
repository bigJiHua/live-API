## 记忆、用户画像与自定义规则

前端入口为「聊天设置 → AI 个性化」，页面有「记忆」「AI 对我的了解」「自定义规则」三个页签。记忆可搜索、查看、新建、编辑、停用、删除和恢复历史版本，也可在聊天中明确要求 AI 修改或删除。用户画像按背景、喜欢、不喜欢、目标、沟通、工作方式分类，AI 整理的条目带可核对的用户原话，初始为未确认；用户可确认、修正、新增或删除。启用的规则作为后续模型请求中的明确用户要求，例如先给结论、避免无意义赞美和回答语言。

固定说明在提示词前缀，变化的规则、画像和记忆索引放入 `TASK_INPUT.personalization`。本轮明确要求优先于已保存偏好，用户维护或确认的画像优先于未确认推断；规则不提供工具执行授权。无条件语言规则支持确定性处理，条件或多句语言规则交给模型理解，避免默认提问语言覆盖已定义的条件。现有私有资料访问与供应商授权边界继续复验。用户可分别关闭记忆、画像及自动画像整理。

画像从本人跨聊天的用户消息与启用的记忆整理，不把助手猜测作为来源。自动整理在成功聊天后异步触发，默认至少有 8 条新用户消息且距上次整理 30 分钟；同一进程内失败的自动尝试也进入冷却，记录最多 2000 个用户，重启不保留该失败冷却。每批最多 80 条历史消息、一次模型调用，计入现有日调用额度。手工「更新」增量处理，「重建」仍只查看最近 80 条用户消息和本次容量内的资料，保留尚未检查来源的旧推断及用户维护、确认项，只替换本次明确更正的推断，不能视为清空后全历史重算。来源裁剪后，可信重建调用通过内部 `allowHistoryRewind` 保存实际处理位置，后续增量继续余下历史；公开请求不接收该选项，普通 AI 更新禁止回退，用户维护也不能改写游标。手动生成不受自动尝试冷却限制。删除的画像及记忆来源会被抑制，旧历史不能自动复活同一内容；用户显式恢复或重新添加某条记忆可解除对应内容的抑制，恢复版本中未包含的旧已忘内容保持抑制。

画像模型超时遵循 `AI_PROVIDER_TIMEOUT_MS`（1000～105000 毫秒，默认 60000），总处理额外预留 10 秒；不再固定截断为 30 秒。前端画像生成等待上限为 180 秒，包含排队与持久化余量。部署模板为 `/api/v1/ai/personalization/profile/generate` 单独设置 180 秒读取超时；模板修改不会自动部署到实际反代服务器。每批至多 12 项、每项正文 120 字、证据至多 2 段且每段逐字原话 100 字，任务输出上限 8192 tokens，按真实模型能力、显式较小的 `maxOutputTokens` 及总预算继续收窄；输入估算计入提示词及 schema，裁剪资料后保留续处理游标。当前未知网关实际 4096 tokens 对应最多 6 项。存储最多 100 项，模型既有条目窗口为 30 项；已有用户画像不按新生成上限删除。不完整或超预算结果保留已有画像，明确报错且不自动重试。

## 待补记账与账户纠正

聊天和历史消息中的 `pendingTask` 仅展示已核验来源的金额、日期、缺项及任务编号／版本。`GET /v3/transaction/pending?conversationId=...` 读取当前聊天最新任务；过期任务可展示，但不能自动续接。用户在待补卡明确操作后，`POST /v3/transaction/pending/resume` 接受 `{conversationId,taskId,revision,itemIndex}`，重新核验并恢复同一候选，已有草稿则返回原草稿。账户、分类、支付方式在原财务核查表单补全，不调用模型。

恢复接口不接收金额或日期。被绑定的候选不能修改原金额、方向、币种及日期；最新任务、用户、会话、版本和候选状态在服务端核验。候选仍按原短期生命周期运行，显式恢复刷新同一身份；已取消候选不能复活，完成整批本地成稿后结束对应待补任务。无新增数据库迁移。

## 大范围查询

沿用 V3 原生工具 `query_data`，不增加可执行任意 SQL 的接口。`datasetId` 仍从现有 23 个数据集中选择，日期、筛选和用户权限在服务端核验。

```json
{"datasetId":"finance-monthly","startDate":"2023-11-12","endDate":"2026-11-12","resolution":"auto"}
```

- `auto`：按数据集和范围选择粒度；三年收支可完整返回 37 个月。分基金、工作、事件状态等维度的月组过多时可改为年度，实际粒度明确返回。统计通常省略 `limit`，聚合窗口最多 50 行。
- `month/year`：保持明确指定的粒度，结果多时提供续页，不暗中换粒度。
- `detail`：保持逐笔或逐日明细；金额极值仍在 SQL 全范围筛选排序后确定。金额和笔数不由模型从明细页加总。
- `cursor`：续查时复制上一结果 `queryMeta.page.nextCursor`。凭据绑定用户、数据集、日期、筛选、排序和粒度，15 分钟有效；改变范围或篡改凭据会被拒绝。最大续查偏移 100000。

支持时间聚合的数据集：收支月度／每日、卡消费、还款、工资、基金收益、预算、待办、资产快照和手动登记。余额、卡片配置、工资规则、持仓等当前保存状态仍按各自语义读取，日期不能重建过去状态。

返回信息：`requestedScope/effectiveScope` 表示原请求及实际范围；`resolution` 表示实际粒度；`sourceRecordCount` 表示查询来源数量，`matchedRowCount` 表示匹配的明细或分组数量，`returnedRowCount` 表示本次展示行数。`page` 包含 `offset/limit/hasMore/nextCursor`。`rowsComplete` 只在第一页返回全部匹配行时成立，尾页没有下一页并不等于该页包含全部历史。`summaryComplete` 单独说明 SQL 摘要覆盖情况。

大明细先压缩展示窗口再经过原预览和授权链；完整摘要及日期不缩水，续页从实际披露的最后一行继续。单工具 16 KiB、整轮 64 KiB、8 次工具和 5 次模型预算保留。各页为实时只读查询，不保证多次请求间数据库不变。

“下一页”会承接上一查询主体、日期、筛选、粒度和有效凭据。分页及粒度纳入查询去重身份，第二页不会误用第一页缓存。基金全范围收益和本金增持可进入最终答复，保留四位精度；单只基金与整个组合的总额分别核验。

4. AI 继续推理、归类、追问或返回提案。缺账户由 AI 追问，“余额支付”不等于微信。金额/日期字面验证只核查 AI 已选结果，不负责业务意图或分类。普通财务查询直接展示经证据校验的模型正文，收入、支出、净收支和笔数不再作为强制前缀，明细表也不重复追加；完整摘要和记录保留在数据卡。`scrubModelProse` 按本轮获准数据核验金额、笔数、日期、范围及相关结论，无法核验的句子删除；没有可用正文时才提供服务端已发布事实作为备用回答。排名、逐卡月度事实、多主体独立事实和卡片数量的部分覆盖表仍有专用处理。详见[自然表达补齐](../../../logs/CHANGELOG_2026-11-10_AI_QUERY_SUMMARY_UNIFY.md)。
5. 结构、原话依据、账户、权限及资金检查通过后，草稿/提案、聊天和恢复回执同事务保存。核对、修改和正式提交由用户操作；执行器只接收库存档 ID 与版本，事务复验并返回幂等回执。

每轮最多 5 次模型、8 次工具、120 秒；重复工具停止。V3 文字聊天每日默认 100 次模型调用尝试（上海日界，`AI_V3_DAILY_PROVIDER_CALLS`），OCR 另有单次预算。持久 `requestId` 去重继续有效；V3 文本 `/v3/chat*` 无额外 HTTP 频率拦截。2026-11-10 起，DB 护栏各环境默认每人 30 次/分钟、并发 1；短时竞争先等待空位（默认 30 秒，每进程/用户最多 8 个等待者），超限返回 `503 AI_REQUEST_BUSY`，窗口耗尽返回 `429 AI_RATE_LIMIT` 与等待秒数。等待阶段通过 SSE `status.stage=queued` 显示，不调用模型，不写入请求回执或占用编号；取消/临时拒绝后可手动重新提交。执行时限从接纳时开始，等待仅重新检查空位，不重试模型。窗口、并发、等待时限与容量可通过 `.env.example` 的对应配置调整。OCR 的 HTTP 6 次/分窗口及设置、草稿等辅助接口策略本次保留。单工具外发最多 16KiB、整轮 64KiB，最多 50 行。每次外发/持久化复查授权、连接和动作开关。未配置供应商定价时不伪报人民币成本。

当前 SenseNova 原生工具阶段使用 `json:false`，最终阶段才用 JSON object；显式支持的供应商可配置 `AI_RESPONSE_FORMAT=json_schema`。原生阶段无工具调用的回复统一作为中间结果，进入一次无工具 JSON 收尾，最终阶段才允许校验和生成草稿，整轮预算仍是 5 次。无数据聊天通常 2 次模型，一次工具后通常 3 次；该步骤是协议阶段，不是 HTTP 失败重试。唯一完整 JSON 的文字封装可严格解封；代码不改写金额、方向、日期、账户、分类等业务字段，但会做两处有限规范化（2026-11-07 校准）：`direction` 的精确字符串「0」/「1」转数值（`v3Service.js:223-224`）、必填字段缺失时以服务端提示替换答复文字（`v3Service.js:304`）；账户歧义时会清空 `accountId`（`:250-251`）；最终坏 JSON、非法业务字段或凭空金额/引用立即拒绝。

跨天相对日期使用对应用户原话的服务端日期；后续明确补日期可单独引用。阿拉伯数字、全角、中文金额和万/千单位仅作字面等价验证；尾号、年份或商户“一鸣/七喜”等不能当金额。历史金融/工资/收益本月结束日超出今天时明确收窄到今天；合法查询超过十二个月时只读最近十二个月，并通过 `queryNotice/rangeIncomplete/summary.incomplete` 明示未包含更早历史。未来起点、非法日期、身份/SQL 参数拒绝。

模板版本/摘要在 `v3Prompt.js`，调用、工具、字节量、实际 scope、usage、时长与错误落审计。API 标准输出记录 traceId、供应商 HTTP 状态、错误码和脱敏错误信息。公开列名与凭据字段分开处理，便于工具结果与加密授权证物精确对账。

中间结果回灌只保留本轮已授权 `refMap` 中的随机引用；旧引用、未知引用、UUID 和凭据仍隐藏，不重建或扩大全局引用权限。最终答复的明确当前完成声明须与本轮实际草稿/提案或执行回执一致，否则 `502 AI_RESULT_CLAIM_MISMATCH` 并回滚整个结果事务；用户既有付款描述、未来/否定、历史汇总和引用状态保留。该检查是有限的结果一致性验证，不能证明任意自然语言事实；实际草稿卡和入账回执是最终状态依据。

## V3 接口

前缀 `/api/v1/ai` 是项目公共命名空间，不表示旧 AI V1 编排启用。沿用正式鉴权、请求安全头、AES/PIN 和禁止缓存；不存在生产测试身份白名单。

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/v3/chat`、`/v3/chat/stream` | 原话与会话，一条受控 AI 主流程；最终结果 `contractVersion:3` |
| GET / POST | `/v3/session` | 当天默认会话；POST 仅 `{kind:'manual'}` |
| GET | `/v3/requests/:requestId` | 仅读回执，绝不重新发 AI |
| GET | `/v3/metrics` | 本人当日文字请求、调用/失败、usage、平均时长、剩余预算、prompt 版本 |
| GET / PUT | `/v3/proposals/:id`、`/v3/drafts/:id` | 读取/修改存档提案或收支草稿 |
| POST | `/v3/proposals/:id/action`、`/execute` | 人工核对/取消/执行 |
| POST | `/v3/drafts/:id/action`、`/commit` | 人工核对/取消/入账，ID+version |
| POST | `/v3/ocr` | 共享图片识别，最多一次模型；内部识别 schema 不构成文字分流 |
| POST | `/v3/transaction/preflight`、`/draft` | 卡片手工字段或 OCR 补项核查，不作为自然语言主流程 |
| GET / DELETE | `/v3/transaction/candidates/:id` | 读取/取消历史或 OCR 候选 |
| GET / PUT / DELETE | `/grant`、`/settings` | 可撤回分域授权、加密连接配置；Key 不回传前端 |
| GET | `/logs`、`/conversations`、`/conversations/:id/messages` | 本人处理记录与历史 |
| GET | `/conversations/:id/events?since=编号` | 同账号当前会话的只读 SSE 状态订阅 |
| GET | `/conversations/:id/sync?since=编号` | 消息增量、请求活动及当前卡片版本的恢复快照 |

`npm run test:ai:v3` 重跑 V3 编排、预算、HTTP 与独立安全测试。真实验收通过 `tools/ai-v3-*`，每场景独立合成 owner/manual 会话，真实供应商、HTTP、SQL 读回、人工入库和重复回执分别留证。正式库不用于验收写入。具体结果以 V3 交付日志为准，旧服务测试只在显式 fixture 归档运行。

## A/B 设备访问同一聊天

2026-11-10 起，可见的当前会话保持一个鉴权 GET SSE 订阅，后端每 2 秒读取数据库状态，仅在有变化时推送；连接 55 秒到期后重新订阅，浏览器另每 15 秒 GET 快照兜底。切会话、隐藏页面或离开时关闭旧订阅。它不是永久事件日志；落库消息的自增编号负责恢复缺失消息，每次连接都重新发送活动及实体版本快照。

- A 端发送后，B 端同步原话、排队/处理阶段和最终消息；草稿、提案、候选的修改、核对、取消、入账和转换状态通过当前存档读取刷新。处理阶段可见，模型逐字输出与思考片段暂不跨端推送。
- 消息按角色、请求/消息编号及卡片 ID 合并，相同原话的两次请求都保留；最终多卡结果占用原等待气泡。应用成功后推进游标，恢复失败或旧会话的异步结果不能造成漏取或混入新会话。永久协议异常停止自动重连/轮询并显示提示，网络异常继续退避恢复。
- 可选图表异常单独显示不可用提示，保留已经通过校验的正文与数据；旧双指标饼图也可只读恢复，不修改原记录。后端仅允许单指标且不含负数的饼图，柱状/折线图可包含多个指标。见 [图表与重复恢复修复](../../../logs/CHANGELOG_2026-11-10_AI_CHART_SYNC_LOOP.md)。
- 本机进行中的卡片操作和更高版本不被同步快照覆盖；历史查询/图表保持原快照，输入框草稿按设备保存。远端删除当前聊天时停止订阅、清空旧会话并显示新建提示。
- 新增 [019 合并迁移](../../../mysql/migrations/019_consolidated_20261111.sql)（含原 024 聊天活动表）；运行 `npm run ai:chat-sync:migrate` 专项升级。同步端点只读取，不重放 POST、模型调用或业务执行。活动由执行 token 与终态条件更新，重复请求与晚到阶段不能覆盖原执行。创建与删除共享会话行锁，删除同事务清理活动原话；列表沿用 90 天会话清理并清理孤立活动。

实现和测试证据见 [跨设备同步变更日志](../../../logs/CHANGELOG_2026-11-10_AI_CHAT_DEVICE_SYNC.md)，原问题记录见 [同步审查](../../../logs/REVIEW_2026-11-10_AI_CHAT_DEVICE_SYNC.md)。
